## Mandatory project rules (Rules.md)
- source: Rules.md

## Agent topology
- source: Architecture.md (§3, §4)
- notes: START → resolve instrument + provider configuration → fetch market data and instrument metadata → validate freshness/integrity (fail → INSUFFICIENT DATA) → parallel evidence collection (Market Analyst, Trend Agent, Instrument Agent, News Analyst, Sentiment Agent, Research Agent when needed) → Strategy Supervisor → Strategy Agents A..N → normalize and validate agent evidence → Signaling Agent proposes candidate (if any) → deterministic Risk/Eligibility Gate → CEO Decision (TRADE/NO_TRADE/INSUFFICIENT_DATA) → persist decision and evidence snapshot / Trade Journal append / Monitoring and run metrics → END. Backtesting is a separate graph/workflow using historical datasets and the same versioned strategy rules, not a shortcut inside the live analysis path. Monitoring is instrumentation around runs plus a separate health process; it must not alter decisions. Every node output must contain schema_version, agent_name, agent_version, run_id, status (ok|no_setup|insufficient_data|error|skipped), as_of and created_at timestamps with timezone, input_refs/evidence_refs, limitations, and typed domain fields defined in Schema.md. Errors must be structured and sanitized; never use a successful empty string as a substitute for missing evidence.

## Debugging protocol
- source: Debug.md; Rules.md (§6)
- notes: Diagnose one verified failure at a time; do not write a fix before the cause is confirmed. Required bug report fields: Bug ID, observed error, expected behaviour, actual behaviour, reproduction steps, relevant files/code, environment and versions, run/correlation ID, logs (secrets redacted), what has been tried, last known working revision. Workflow: (1) restate; (2) rank 3–5 root causes only where evidence supports them, with probability ranking and supporting/contradicting evidence, affected component and missing evidence — do not manufacture numerical probabilities; (3) one fast diagnostic per cause that must not change production behaviour or expose secrets; (4) stop and wait for results; (5) after confirmation, state cause and evidence, propose the smallest fix, add/update a regression test, list exact verification commands, record files changed and unresolved risks, update Task.md and Memory.md only after verification succeeds. Prohibitions: no unrelated refactors; no disabling tests/validation/security controls/risk gates; no fake market data to mask a provider failure; no catching and ignoring exceptions; no infinite retries; no claiming a bug fixed until regression and reproduction pass.
