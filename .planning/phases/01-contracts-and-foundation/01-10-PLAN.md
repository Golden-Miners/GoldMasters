<objective>
Complete the configuration surface: every key declared explicitly, a missing or invalid value stopping startup with the offending key named, a deterministic effective-config hash that covers the non-secret settings and nothing else, and the two committed reference documents (`config/goldmasters.yaml`, `.env.example`) that describe that same key set without carrying a secret.

Purpose: D-36 requires configuration errors to be loud and specific — a process that starts with a silently defaulted database URL produces runs whose provenance is wrong. D-15/D-27 require the effective-configuration hash on every run and decision, which makes the hash's canonicalisation a contract: if it covers a secret, secrets leak into records; if it is order-sensitive, spurious configuration changes appear. Splitting this off the original plan-01 keeps each plan inside the file budget while leaving the guarantee intact.

Output: the extended `settings.py` (full key set plus `hash_effective_config`), `config/goldmasters.yaml`, `.env.example`, and the two unit modules that prove the fail-startup, hash and coverage rules.
</objective>
