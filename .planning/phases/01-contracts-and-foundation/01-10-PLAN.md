<objective>
Complete the configuration surface: every key declared explicitly, a missing or invalid value stopping startup with the offending key named, a deterministic effective-config hash that covers the non-secret settings and nothing else, and the versioned `config/goldmasters.yaml` document wired as the lowest-priority settings source for the non-secret defaults, alongside the committed `.env.example` that enumerates the same key set without carrying a secret.

Purpose: D-36 requires configuration errors to be loud and specific — a process that starts with a silently defaulted database URL produces runs whose provenance is wrong. D-15 also puts the non-secret settings in the versioned config document rather than in code, so that document is wired as a real source (the environment and `.env` still win, and secrets arrive only from `GOLDMASTERS_`-prefixed variables), which is also what makes RESEARCH.md's `pyyaml` entry load-bearing rather than decorative. D-15/D-27 require the effective-configuration hash on every run and decision, which makes the hash's canonicalisation a contract: if it covers a secret, secrets leak into records; if it is order-sensitive, spurious configuration changes appear. Splitting this off the original plan-01 keeps each plan inside the file budget while leaving the guarantee intact.

Output: the extended `settings.py` (full declared key set, the versioned-document source, plus `hash_effective_config`), `config/goldmasters.yaml`, `.env.example`, and the two unit modules that prove the fail-startup, hash, document-source and coverage rules.
</objective>
