<objective>
Prove the phase's architectural spine end-to-end on one path: a canonical Pydantic contract from the contracts package is exported to committed JSON Schema, imported by a FastAPI backend that resolves a typed settings object once at startup, binds loopback-only, and answers a `/health` surface whose contents prove the chain (status, version, contract schema version, config hash, database reachability).

Purpose: this is the phase's end-to-end tracer. It carries the single path from the contract layer through the export generator, the settings model, the app's `lifespan`, the loopback guard and the health surface. If the spine is wrong we learn it in one commit instead of after eleven. The modules here are written for keeps: plans 09 and 10 extend `app.py` and `settings.py`, and Phase 2 onward builds the real API on this skeleton. It was split out of the original plan-01 (26 declared files) so each plan stays inside the file budget; the contracts core it depends on is plan 01, and the observability and configuration surfaces that used to share that plan are now plans 09 and 10.

Output: the `apps/api` distribution wired into the workspace, `packages/contracts/_export_schema.py` with the committed `envelope.json`, `settings.py`, `app.py` with `lifespan`/loopback guard, `health.py` with the five-field surface, and `tests/integration/test_health.py`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process → network | the API process binds a socket; a non-loopback bind would expose it off-host |
| process → database | the probe opens an outbound connection using a credential-bearing URL |
| contract models → committed schema | the export generator turns models into the committed document every later phase reads |
| environment → process | the bound host and database URL arrive as `GOLDMASTERS_`-prefixed environment variables |
