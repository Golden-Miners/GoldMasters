<objective>
Turn the contract layer into *evidence*: prove it is pure, prove the committed schema matches the models, and prove every contract rejects the mutations Schema.md's invariants forbid.

Purpose: criterion 1 requires the contracts as *validated* versioned code — validation is only proven by a suite that rejects what the schema forbids (D-06). D-08 requires purity to be enforced, not merely intended. D-10 requires the committed JSON Schema to be provably regenerable, so the TypeScript generator and every later phase read a document that provably came from the models. The accepted-case set is authored once here so plan 06's persistence round-trip exercises exactly the same payloads.

Output: the purity AST test, the schema drift test, and the golden conformance suite with its shared accepted/rejected case module.

Wave note: this plan moved from wave 3 to wave 4 and now depends on plan 11, because its schema drift test compares the *complete* committed `packages/contracts/schema/*.json` set against a fresh export, and plan 11 is the plan that completes that set (news, sentiment, backtest) and derives the export enumeration from the package barrel.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| contracts package → consumers | every later phase and the type generator import this package; an impure dependency would leak a runtime library into all of them |
| committed schema → generators | the committed JSON Schema is the input to the TypeScript generator; a drifted document would generate wrong types |
| untrusted payload → contracts package | the conformance suite is the standing proof that each contract rejects the mutations Schema.md forbids |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-13 | Tampering | `packages/contracts/schema/*.json` | high | mitigate | The drift test regenerates into a temp directory and byte-compares against the committed documents after CRLF normalisation; the gate fails on divergence (D-10; Pitfall 8). |
| T-01-14 | Tampering | contracts-package imports | high | mitigate | An AST purity test with an in-test allowlist fails on any non-allowlisted root, so broadening the dependency surface is a visible diff (D-08). |
| T-01-15 | Tampering | `tests/contract/` conformance suite | high | mitigate | Every contract gets accepted cases plus rejected mutations for each D-06 class and each named Schema.md invariant; a coverage guard prevents a contract from shipping without evidence. |
| T-01-SC | Tampering | `uv`/`npm`/`pip` installs | high | mitigate | Package-legitimacy audit exists in RESEARCH.md (all `SUS` verified as checker artifacts, independently approved); the dependency allowlist test from plan 02 covers declared dependencies; no `[SLOP]` packages. |
