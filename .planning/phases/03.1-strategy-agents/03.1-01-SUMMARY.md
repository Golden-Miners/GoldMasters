## Decisions Made

- Per-agent numeric rule params deferred to agent phases: their plans carry the operator-spec rule family as precondition with a halt-if-missing gate. Declaring named numerics here would invent thresholds, so the 3.1 scaffold carries only the 5 matrix fields per agent (ENABLED/instruments/timeframes/regimes/min_bars), all fail-closed. Agent phases add their numerics alongside the operator spec.
- `eligible_agents` never excludes on bar count (locked 3-valued return has no insufficient-data member); below `min_bars` the agent still runs and reports `INSUFFICIENT_DATA` via `meets_min_bars` at evaluate time. The min_bars test asserts exactly this split.
- `build_levels_evaluation` imports `risk.levels` function-locally: `risk/levels.py` imports `RuleCheck` from `base`, so a top-level import would cycle.
- `NoDecode` + comma-split for strategy list settings: pydantic-settings JSON-decodes complex env values before validators run, so bare `list[]` fields reject `H1,H4` with `SettingsError`. `NoDecode` keeps raw text for the split; unknown enum members still fail startup naming the field.
