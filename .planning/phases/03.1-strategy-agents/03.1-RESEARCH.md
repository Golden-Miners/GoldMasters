## MarketContext fields (locked shape)

```python
class MarketContext(ContractModel):  # strategies/base.py, phase 3.1
    instrument_id: str
    provider_id: ProviderId
    timeframe: Timeframe
    regime: TrendRegime            # from domain/regime.classify_regime; UNKNOWN allowed
    quality_status: QualityStatus  # batch verdict; MALFORMED/STALE/etc. visible here
    quality_flags: list[QualityFlag]
    volume_type: VolumeType        # TICK | EXCHANGE | BROKER | UNKNOWN | NOT_AVAILABLE (enums.py:121-128)
    tick_size: str | None          # decimal-string; None = unknown precision, skip alignment (Phase-2 precedent)
    contract_size: str | None      # decimal-string; None = unknown provenance (precision.py:40-47, D-3.4)
    bar_count: int
    now_utc: UtcDatetime            # explicit clock (validation.py precedent)
```

Rationale per field: agents need regime (eligibility + rule branching), quality (fail-closed without re-validating), `volume_type` (never relabel tick as exchange — Schema §4, enums.py:122), tick/contract size (quantization + risk sizing context; `None` = skip, never default). No price/volume data inside ctx — bars remain the sole price input (closed bars only; forming-bar exclusion is Phase-2 validated input contract).

## Status-mapping rules (locked)

Adapter in `base.py` (3.1): agent outcome → one of `SETUP_FOUND | NO_SETUP | INSUFFICIENT_DATA | NOT_APPLICABLE`, then:

| Adapter status | `StrategyEvaluation` | `AgentRunStatus` (Schema §2 / enums.py:45-56) | Gate input? |
|---|---|---|---|
| `SETUP_FOUND` | `setup_found=True` + levels (validator-enforced) | `ok` | Yes — candidate flows to `evaluate_gate` |
| `NO_SETUP` | `setup_found=False`, null levels | `no_setup` | No (nothing to validate; recorded with rule_checks) |
| `INSUFFICIENT_DATA` | `setup_found=False`, null levels, reason cites cause | `insufficient_data` | No |
| `NOT_APPLICABLE` | `setup_found=False`, null levels, reason cites scope mismatch | `skipped` (Schema §2 has no `not_applicable`; `skipped` is the verbatim member) | No — never reaches gate |

Mapping triggers (locked): `INSUFFICIENT_DATA` when bars < agent's minimum count, precision unknown where required, regime UNKNOWN where the agent needs direction, or `check_bar_order` MALFORMED (conventions.py:91-104 — never sort). `NOT_APPLICABLE` when the eligibility matrix excludes this (instrument/timeframe/regime/scope, incl. legs the agent does not define — the Agent-10 "NOT_APPLICABLE legs" case: an agent whose contract declares e.g. no short leg returns NOT_APPLICABLE for short-direction contexts rather than forcing NO_SETUP, preserving the distinction between "looked, absent" and "out of scope"). The existing `StrategyEvaluation` validator is untouched — all four states satisfy it since only SETUP_FOUND carries levels. `AgentRunStatus` gains NO new member (closed enum, D-23); NOT_APPLICABLE lives on the adapter + `StrategyEvaluation.limitations`/reason strings.

## Eligibility-matrix shape (locked)

```python
class EligibilityRule(ContractModel):  # strategies/base.py, phase 3.1
    strategy_id: str
    enabled: bool                                   # GOLDMASTERS_STRATEGY_<ID>_ENABLED
    instruments: list[str]                          # canonical ids; empty = none (never "all" by default)
    timeframes: list[Timeframe]
    regimes: list[TrendRegime]                      # regimes the agent evaluates in; others → NOT_APPLICABLE
    min_bars: int = Field(ge=1)                     # below → INSUFFICIENT_DATA, never a guess
def eligible_agents(matrix: list[EligibilityRule], ctx: MarketContext) -> dict[str, Literal["eligible","not_applicable","disabled"]]
```

Matrix is versioned code + settings-driven values (lists arrive via `GOLDMASTERS_STRATEGY_<ID>_*` fields; no literal lists in agent packages). Supervisor (Phase 4) consumes `eligible_agents`; phases 3.1–3.5 test it with the Agent-10 row. Matrix additions per agent land in that agent's own phase (ownership isolation).

## Per-agent test list (every agent phase; colocated, not deferred)

Per agent `tests/unit/test_agent_<id>.py`: (1) all-pass → SETUP_FOUND + levels + id/version/hash stamp; (2) each rule fail individually → NO_SETUP + null levels; (3) `unknown` verdict → NO_SETUP + null levels; (4) cheat-rejection: hand-constructed `StrategyEvaluation(setup_found=True, levels=…)` on failed checks raises (base validator — test_strategies.py:126-151 precedent); (5) INSUFFICIENT_DATA: fewer than min_bars, unknown precision where required, UNKNOWN regime where directional; (6) NOT_APPLICABLE: out-of-scope regime/instrument/timeframe + each non-defined leg → `skipped`, never gate input; (7) **no-look-ahead**: identical prefix with different future bars → identical output (evaluate on `bars[:k]` vs full series must match for the first k; plus a probe where a setup-visible future bar is appended and the evaluation at the earlier index is unchanged); (8) determinism: identical in → identical out, twice; (9) Decimal-only: no float in rule path (AST scan precedent per 03-VERIFICATION truth 2); (10) misordered input → INSUFFICIENT_DATA, order preserved (conventions.check_bar_order precedent). ## Common Pitfalls (new for this workstream)

1. **Invented rule thresholds** — any numeric literal beyond 0/1 structural constants in `strategies/` fails review; params via Settings or phase blocks.
2. **Look-ahead via full-series indicators** — indicator computed over all bars then sliced; tests in list item (7) catch it. Rule: functions take only the bars they may read.
3. **NOT_APPLICABLE laundered into NO_SETUP** — collapses "out of scope" with "looked, absent", corrupting supervisor stats; adapter test asserts distinct mapping.
4. **Cross-agent imports** — shared code migrates to `domain/`, never agent-to-agent.
5. **Backtest creep into 3.x** — historical runner/metrics belong to Phase 6; 3.x tests are vector-only.
